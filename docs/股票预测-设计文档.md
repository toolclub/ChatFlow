## 0. 结论速览

- 本功能是现有「智能选股」的**同级子页面**，不重构选股，只新增「股票预测」工作区 + 一条独立预测图（LangGraph）。
- **最大化复用**现有 quant 基建：provider/数据适配器、缓存、`BaseNode.emit_thinking`、SSE 驱动、`quant_store` 异步 CRUD 范式、`QuantView.vue`/`useQuant.ts` 前端三件套。**新建**的只有：预测领域模型、预测图与节点、预测 store、预测 router、`fsm/prediction.py` 状态机、预测专用 SSE 事件、`PredictionView.vue`/`usePrediction.ts`/`PredictionChart.vue`。
- **鉴权**：复用现有 `ADMIN_SECRET_KEY` + `verify_admin_access` 机制（**不新建鉴权**），把「智能选股」和「股票预测」同时改为管理员密码门禁（前端拦截 + 后端 `Depends` 鉴权）。
- **资讯搜索**：复用 Tavily（`TAVILY_API_KEY` 已配置），但用**独立于聊天轮次预算**的 per-prediction 预算（不沿用 `web_search` 工具的 5 次/轮上限）。9+ 维度由 LLM（`CHAT_MODEL`=deepseek-v4-pro）生成查询、汇总、打情绪分。
- **预测方法（MVP）**：技术指标（MA/EMA/MACD/RSI/布林/KDJ）+ ARIMA（方向）+ GARCH（波动率）+ 蒙特卡洛（置信区间，非单一曲线）+ 资讯情绪修正因子。LSTM/Prophet 等 ML 模型**延后到 v2**（无模型产物存储基建）。
- **实时更新**：**SSE**（与全平台一致），非轮询/WebSocket。单条 SSE 流贯穿 资讯搜索→模型推理→完成，刷新断线走 full-state 轮询兜底。
- **免责声明**：预测页与结果页均有醒目免责声明。

## 2. 功能一：权限控制（智能选股 + 股票预测）

### 2.1 设计原则
- **复用不新建**：沿用 `ADMIN_SECRET_KEY`（env，已加密）+ `verify_admin_access` + `POST /api/admin/verify` + `X-Admin-Key` header + 前端内存 ref。
- **前端拦截 + 后端鉴权双保险**：前端门禁弹窗只是 UX，真正的拦截在后端 `Depends(verify_admin_access)`（铁律 #1：状态来自后端 403，不靠前端 v-show）。
- **一次解锁，两页通用**：抽一个 `useAdmin()` composable 持有 `verifiedAdminKey`，智能选股与股票预测共享同一已验证会话。

### 2.2 后端改动
1. 把 `verify_admin_access` + `ADMIN_SECRET_KEY` 从 `admin_router.py` 上提到 `services/auth/dependencies.py`，导出共享依赖别名：
   ```python
   # services/auth/dependencies.py（新增）
   async def verify_admin_access(x_admin_key: str = Header(None)) -> bool:
       if x_admin_key != ADMIN_SECRET_KEY:
           raise HTTPException(status_code=403, detail="管理员权限验证失败")
       return True
   AdminRequired = Annotated[bool, Depends(verify_admin_access)]
   ```
   `admin_router.py` 改为 import 这个共享依赖（消除重复）。
2. 给 `quant/router.py` 的**业务端点**加 `admin: AdminRequired`（`/screen` `/snapshot/{id}` `/snapshot/{id}/analyze` `/session/active` `/stock/{symbol}/chart`；`/status` 可放行探活）。⚠️ 这会给现有「智能选股」也加门禁——**这是用户明确要求的**（"两个子页面入口均需要管理员密码校验"）。如需灰度，可加 `QUANT_ADMIN_GATED` 开关。
3. 新建 `routers/prediction_router.py`（prefix `/api/prediction`），每个端点都带 `admin: AdminRequired`。
4. 密码源仍是 `config.ADMIN_SECRET_KEY`（`.env`，`ENC(...)` 加密），**默认占位值**仅本地开发用——符合铁律"不硬编码、从环境变量读"。

### 2.3 前端改动

## 3. 功能二：股票预测页面

### 3.1 预测记录列表 + 状态机

**状态枚举（`fsm/prediction.py` 新建，遵循铁律 #6——真正的 `(str, Enum)`，不是字符串字面量）**：

| 状态值 | 中文 | 含义 |
|---|---|---|
| `queued` | 排队中 | 已入库占位行，尚未开始 |
| `news_searching` | 资讯搜索中 | 跑 9+ 维 Tavily 资讯 + LLM 情绪打分 |
| `inferring` | 模型推理中 | 跑技术指标 + ARIMA/GARCH + 蒙特卡洛 + LLM 综合推理 |
| `done` | 已完成 | 预测结果 + K 线 + 拐点 + 分析已落库 |
| `failed` | 失败 | 任一阶段异常（资讯全挂/数据不足/模型报错） |

**状态流转**：
```
queued ─start→ news_searching ─news_done→ inferring ─infer_done→ done
                    └─fail→ failed            └─fail→ failed
```
- 转换由 `PredictionSM` 校验后**先改状态再写库**（铁律 #6）。DB `prediction_snapshots.status` 存枚举值。
- 任一阶段异常 → `failed` + `error_message` 字段记录原因（铁律 #9 不吞异常）。
- 服务重启时 `cleanup_stale_prediction_sessions()` 把卡在 `queued/news_searching/inferring` 的旧任务标记 `failed`（仿 `cleanup_stale_quant_sessions`）。

**el-table 列表**（复用 `QuantView.vue` 的 el-table 样式）：
- 列：时间 / 标的(symbol+名称) / 市场(A股|美股) / 状态(带颜色 tag，按枚举着色) / 预测方向(↑/↓+幅度) / 置信区间 / 操作(查看详情)。
- 点「查看详情」→ 进入交互页面（§3.5），复用流式展示逻辑把已落库的 `thinking_segments` / `news` / `forecast` / K 线数据回放渲染。
- 列表数据源：`GET /api/prediction/records?market=&limit=` 分页查该用户的预测记录。

**每个维度的搜索方式 + 汇总喂给模型**：

- **搜索引擎**：Tavily（`tools/builtin/web_search.py` 同款 API：`POST https://api.tavily.com/search`，`include_answer=true` + `chunks_per_source=3` + `max_results=6`，重试 3 次指数退避）。
- **查询生成**：每个维度由 LLM（`CHAT_MODEL`=deepseek-v4-pro，流式）根据「标的+市场+维度」生成 1–2 条中文/英文关键词（A股偏中文财媒、美股偏英文）。例如 #1 对「AAPL 美股」→ `"Apple geopolitical risk China supply chain 2026"`；对「000001.SZ 平安银行 A股」→ `"平安银行 地缘政治 制裁 风险"`。
- **预算隔离**：**不沿用** `web_search` 工具的 5 次/轮上限（那挂在聊天 `msg_id/conv_id` scope，预测图跑在独立 graph 里会落到 `_default` 共享计数，9 维立刻打爆）。预测节点直接调 Tavily 客户端（从 `web_search.py` 抽出 ~15 行 httpx POST + `_normalize_result` 复用），用 **per-prediction scope**（key=`chatflow:prediction:websearch:{prediction_id}`），上限按维度数 × 2（留重试空间，MVP 12 维 → 24 次）。
- **去重 + 缓存**：同维度同 query 命中本轮缓存（仿 `web_search` 的 `_maybe_get_cached`）；跨维度结果按 url 去重。
- **汇总喂模型**：把 12 维的 `{维度, tavily_answer, top3 片段摘要}` 结构化打包成 JSON（**走独立字段 `news_digest` JSONB，不塞 content**——铁律 #2）。LLM 第二次流式调用读 `news_digest` → 对每维打情绪分 `-1..+1` + 一句理由 + 综合 `news_sentiment` 标量（作为蒙特卡洛漂移修正因子，见 §3.3）。整个搜索 + 打分过程流式推送 `NEWS_ITEM` / `THINKING` SSE 事件到前端。

### 3.3 预测计算方法（MVP 选型 + 可解释性）

**MVP 选型（1 周走势）**：

| 方法 | 作用 | 依赖 | 输出 |
|---|---|---|---|
| 技术指标 MA/EMA/MACD/RSI/布林/KDJ | 描述当前技术面状态 + 信号 | `pandas-ta`（或手撸） | 指标值 + 多空信号标签 |
| ARIMA(p,d,q) | 价格方向（未来 5 交易日点预测） | `statsmodels.tsa.arima` | 5 日点预测序列 |
| GARCH(1,1) | 未来 5 日**波动率**路径（决定置信带宽） | `arch` 包 | 5 日条件方差序列 |
| 蒙特卡洛模拟（GBM） | **置信区间而非单一曲线**：用 ARIMA 漂移 + GARCH 波动率跑 N=2000 条路径，取 10/50/90 分位 | `numpy`（已有） | 5 日价格分布 + 置信带 |
| 资讯情绪修正因子 | 把 `news_sentiment`（-1..+1）转为漂移偏移注入 GBM drift | 复用 §3.2 LLM 打分 | 修正后漂移 μ' |

**与资讯搜索结合的方式（资讯情绪作为修正因子，你明确要求的）**：
- GBM 漂移 `μ = ARIMA 年化漂移 + α · news_sentiment`，`α` 控制资讯权重（可配，默认让资讯能在 ±年化 15% 范围内修正方向）。
- 极端资讯（如 #19 黑天鹅、#1 战争）若情绪 |分|>0.7，额外对 GARCH 波动率乘扩大因子（事件型波动率飙升），使置信带变宽——**"不确定性高时区间变宽"**符合直觉。
- 技术指标若与资讯方向冲突（如 RSI 超卖偏多 vs 资讯偏空），LLM 综合推理节点显式指出分歧并给倾向（不强行融合成单一数字）。

**延后到 v2（不进 MVP）**：LSTM/Prophet/梯度提升回归等 ML 模型。原因：① 无模型产物存储/版本基建（critique 确认）；② 单标的 fit-per-request 的 ARIMA/GARCH/蒙特卡洛已能给出方向 + 置信区间，满足"1 周走势 + 置信区间"诉求；③ ML 需要训练数据管线 + 回测框架，超出 MVP。结构上把计算层做成 `PredictionEngine` 策略接口，v2 可插入 LSTM strategy 不动上层。

**可解释性呈现（你明确要求的"计算逻辑的可解释性"）**：
- 结果页分四块展示：
  1. **原始数据**：行情 OHLCV 摘要（最近 60 日）+ 12 维资讯摘要（每维一句 + 情绪分）。
  2. **计算公式与方法**：列出每个方法的公式 + 关键参数（ARIMA 阶数、GARCH α/β、蒙特卡洛 N、资讯权重 α）+ 该方法对本标的的具体输出值。
  3. **模型推理过程**：流式 think（`emit_thinking` 推 reasoning/content），展示 LLM 如何综合技术面 + 资讯面 + 统计模型得出结论。
  4. **K 线图**（§3.5）：历史实线 + 预测红色虚线 + 拐点 + 置信带。
- 蒙特卡洛**不画单一确定性曲线**，画中位线 + 10/90 分位置信带阴影（直观传达不确定性）。

### 3.5 用户交互流程 + 实时更新选型

**流程**：
1. 「股票预测」工作区 → 顶部「预测」按钮 → 弹模态框选 **A股 / 美股**（el-radio，目前仅这两种）。
2. 选完进入「标的输入」：A股 输入代码/名称（akshare 模糊搜索），美股输入 ticker。可选预测方法套餐（默认 MVP 全套）。
3. 提交 → `POST /api/prediction` 立即返回 `prediction_id`（status=`queued`），后台 `asyncio.create_task(background_predict)`（仿 `background_screen`）。
4. 前端进入**交互页面**（复用对话式 AI 交互范式，仿 `QuantView` 流式分析面板）：
   - 实时展示：原始行情数据摘要、12 维资讯搜索结果（逐条 `NEWS_ITEM` 流入）、计算公式与参数、模型 think 过程（流式）、K 线图（done 后渲染）。
   - 进度按状态机 tag 着色（排队中/资讯搜索中/模型推理中/已完成/失败）。
5. 完成后：K 线图（历史实线 + 预测红色虚线 + 拐点 + 置信带）+ 免责声明 + 「接入对话深挖」按钮（仿 `continueWithSnapshot`，把 `prediction_id` 经 `contextRefs:[{type:'prediction_snapshot',id}]` 喂给对话，LLM 查库深挖）。

**K 线图（ECharts）规格**：
- 克隆 `StockDetailView.vue` 的 candlestick 配置（up `#F25D59`/down `#00B178`）+ MA5/10/20 + dataZoom + 生命周期。
- **预测段**：第二条 `type:'line'` series，`lineStyle:{color:'#FB7299',type:'dashed',width:2}`，`showSymbol:false`，数据用 null 桥接到最后一根历史收盘（x 轴索引延伸到未来 5 个交易日）。
- **拐点**：`markPoint`（`symbol:'pin'`）标在预测曲线的局部极值（方向反转点）。
- **置信带**：第三条 `type:'line'` area（10/90 分位）半透明阴影包住预测中位线——直接呈现"蒙特卡洛置信区间而非单一曲线"。
- 新建独立组件 `PredictionChart.vue`（props `{symbol, historicalData, forecastData, inflectionPoints, confidenceBand}`），**不 retrofit `StockDetailView`**（它写死历史-only）。

**实时更新选型：SSE（非轮询/WebSocket）**。理由：
1. **全平台一致性**：spec 铁律 #3/#6 + `graph/runner/stream.py` SSE 驱动 + `streamQuantAnalyze` 已验证；预测就是 `analyze_graph` 的多节点泛化，天然 SSE。
2. **场景匹配**：预测是**服务端→客户端**单向流式（think/资讯/结果增量），无需客户端→服务端双向——WebSocket 的双向优势用不上，纯增负担。
3. **比轮询优**：分钟级计算，轮询要么太粗（丢 think 增量）要么太密（打垮后端，spec 踩坑"用户猛刷新打垮后端"已修过）；SSE 天然增量 + 心跳。
4. **比 WebSocket 简**：无需连接升级、过 nginx 代理原生支持、`EventSource`/ReadableStream 自动重连；平台已有 SSE `/resume` 断线重放（`event_log.id` 有序）+ Redis 心跳。
5. **断线恢复**：单条 SSE 流贯穿 `news_searching→inferring→done` 全阶段；刷新/断线后前端先 `GET /api/prediction/{id}` 拿 full-state（已落库的 thinking_segments/news/forecast）回放，再重连 SSE 续流（仿 `useQuant.checkActiveSession`）。

### 3.6 SSE 事件合规（修正 quant 的既有违规）

> critique 发现：`quant_agent.py` 把 `"delta"` 硬编码进 SSE，但 `SSEEventType` 枚举**没有** `DELTA` 成员（只有 `CONTENT`），前端 parser 却 `ev.event==='delta'`——这是 quant 的既有铁律 #3 违规。**预测功能不沿用这个违规**。

- `fsm/sse_events.py` 新增预测专用成员（加入 `_PRIORITY_ORDER`）：
  - `NEWS_ITEM`（资讯结果流入）
  - `FORECAST`（预测数值结果：方向/幅度/置信区间/拐点）
  - `INFLECTION`（拐点标注，也可并入 FORECAST）
  - `PREDICTION_PROGRESS`（阶段进度，对应状态机转换）
- 内容增量**用注册的 `CONTENT`**（不用 `"delta"`），reasoning 用 `THINKING`，结束用 `DONE`，错误用 `ERROR`。
- 新建前端 `streamPrediction` SSE parser（**独立于** `streamQuantAnalyze`），按上述枚举值分发——不触碰 quant 既有 parser，避免连带破坏。

## 4. 数据流与状态流转（端到端）

```
用户提交预测
  → POST /api/prediction (AdminRequired)
  → save_prediction_snapshot(status=queued)  [DB-first，铁律#1/#4]
  → asyncio.create_task(background_predict(prediction_id, ...))  [立即返回 prediction_id]
  → 前端 GET /api/prediction/{id} 回放 + 连 SSE /api/prediction/{id}/stream

background_predict (prediction graph, astream_events v2):
  [news_search_node]  PredictionSM: queued→news_searching
    - LLM 生成 12 维 query (astream, emit_thinking)
    - per-prediction Tavily 调用 → news_digest JSONB
    - LLM 情绪打分 → news_sentiment
    - yield NEWS_ITEM / THINKING / PREDICTION_PROGRESS
  [compute_node]       PredictionSM: news_searching→inferring
    - get_adapter().bars(symbol, start, end, market) → 1-2yr OHLCV
    - compute 技术指标 + ARIMA + GARCH + 蒙特卡洛(μ修正) → forecast/inflection/conf_band
    - yield FORECAST / THINKING
  [analyze_node]       (LLM 综合, astream, emit_thinking)
    - 综合技术面+资讯面+统计模型 → analysis + risk_notes
  → update_prediction_snapshot(status=done, forecast, news_digest, thinking_segments, ...)
  → yield DONE

失败任一节点 → PredictionSM→failed + error_message + yield ERROR
```

DB `prediction_snapshots`（新建，仿 `quant_snapshots` + 预测列）：
`id, client_id, user_id, conversation_id, criteria(JSONB: {symbol,market,methods,horizon}), market, symbol, status(枚举值), horizon, target_date, predicted_price, predicted_range(JSONB:[low,high]), confidence, model_name, news_digest(JSONB), news_sentiment, forecast(JSONB: 5日点预测序列), inflection_points(JSONB), confidence_band(JSONB), technical_indicators(JSONB), analysis(TEXT), risk_notes(JSONB), thinking_segments(JSONB), error_message, created_at`。
